## The run end to end, without the takes

A scratch folder outside the repository held a take the builder made: the page's `TF2Audio.process` in headless
Chromium on `tests/testsignal/tf2_voice_nettest_v1.wav` (generated by its committed script) with `renderOptions()`
and `volume 0.15`, which the page gave as `codec steam`, `enableWarble true`, `timeline game`, `fps 300`,
`bufferMs 100`; saved as a 16-bit WAV of 58.2 s. Each scratch manifest had one row with that take and that source.

Commands (with `CHROMIUM_EXECUTABLE` set to the installed Chromium):

    flock /tmp/tf2ve-heavy.lock node tests/accuracy.mjs --takes <scratch>/takes --manifest <scratch>/manifest-queue.json --json <scratch>/queue.json
    flock /tmp/tf2ve-heavy.lock node tests/accuracy.mjs --takes <scratch>/takes --manifest <scratch>/manifest-source.json --json <scratch>/source.json

## A choice the order did not make

The order asks for a scratch manifest outside the repository and a run of `node tests/accuracy.mjs --takes
<scratch folder>` on it. The suite read only `tests/accuracy.takes.json`. Editing that file for the run would have
put scratch rows into a committed file, so the builder added `--manifest <file>` (chosen): without it the suite reads
`tests/accuracy.takes.json` as before. It is the smallest change that lets the check run as written.
